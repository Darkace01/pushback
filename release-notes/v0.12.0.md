## New

- **Approve deployments from Pushback.** When a run is waiting for a protected environment's review, its page shows which environments it waits for and who can approve them, with **Approve and deploy** and **Reject** buttons for the ones you can approve. The My work inbox has a new **Approvals** tab, the tray badge counts deployments waiting on you, and you get a notification when one starts waiting (Settings → Notifications → "A deployment is waiting for my approval").

- **Comment on specific lines of a pull request.** The Files tab now shows review conversations under the lines they're about. Reply to them, resolve or unresolve them, or click the **+** next to any line to start a new comment. **Suggest a change** fills in a suggestion block with the line's current text for you to edit. Comments on code that has since changed are listed above the file.

- **GitHub notifications in your inbox.** A new **Notifications** tab in My work shows GitHub's own notifications, including mentions, discussions and releases that the other tabs don't cover, with why you got each one. Opening one marks it read on GitHub, and **Mark all as read** clears the lot. A classic token needs the `notifications` (or `repo`) scope.

- **Run artifacts.** A finished run lists the artifacts it uploaded, with their size and when they expire, and **Download** saves the zip wherever you choose.

- **Job timeline.** Runs with several jobs have a **Timeline** view that draws every job on one time axis, so you can see what ran in parallel and what held the run up. A finished run also says how its time compares with that workflow's usual, for example "35% slower than usual".

- **Actions settings for each repo.** A new section in each repo tab lists Actions **secrets** (names only; values are encrypted before they leave Pushback) and **variables**, with create, edit and delete, shows your **self-hosted runners** with whether each is online or busy, and lists **caches** with their total size, so you can delete one cache or every cache for a branch when CI misbehaves. Most of these need admin rights on the repo, and Pushback says so when your token lacks them.

- **Merge queue view.** A new repo section, also linked from a pull request's merge status, shows the whole merge queue in order: each pull request, its author and state, when it joined and GitHub's estimate of when it will merge.

- **Workflow file viewer.** **View file** in the Workflows widget and **View workflow file** on a run open the workflow's YAML with highlighting and line numbers, at the run's own commit. A **Triggers** summary lists what starts the workflow, and **Why didn't it run?** checks an event, branch and changed paths against its filters.

- **Milestones.** The Issues section has a Milestones view with each milestone's progress and due date, a milestone filter for the issue list, and a way to move an issue to another milestone from the issue view. Saved searches can filter by milestone too.

- **Projects.** Issues and pull requests show which GitHub Projects they're in and their Status in each, and you can change the Status from Pushback. This needs the `read:project` scope to read and `project` to change, and Pushback says when your token lacks them.

- **Discussions.** A new repo section lists discussions by category, with answered state and comment counts. Open one to read it and its replies and to add a comment. Links to discussions open in Pushback.

- **Watch a run.** **Watch** on a run pins it to a small always-on-top window that shows its status, current job and step, and how long it has been running. When it finishes you get a notification, even if that kind of notification is switched off or snoozed. The tray menu lists the runs you're watching.

- **Request reviewers.** The pull request view shows who has reviewed and who is still requested. **Request review** suggests code owners of the changed files, people who reviewed recently and others who can review, and lets you add or remove reviewers.

- **Notification digests.** Notifications held back by quiet hours or a snooze can now be summarised in one notification when the quiet period ends ("While you were away: 3 runs failed, 2 PRs need your review…"). You can also turn on a daily digest at a time you choose. Clicking either opens Activity.

## Improved

- **Branch and tag labels in the commit graph no longer spill over the author's name.** They shrink and are cut off with an ellipsis instead. The commit details panel still lists every one in full.
